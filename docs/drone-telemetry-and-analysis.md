# drone-telemetry & drone-analysis — Reference Documentation

---

## drone-telemetry

### Overview

The `drone-telemetry` crate parses SRT subtitle files generated by DJI drones and converts them into structured telemetry data. The pipeline has three stages:

1. **Parsing** (`parser`) — reads the SRT file, splits it into blocks, extracts fields.
2. **Frames** (`frame`) — represents a single telemetry frame with all fields.
3. **Normalisation** (`normalize`) — converts GPS coordinates to ENU, computes velocities, builds the flight trajectory.

The crate uses **tolerant parsing**: invalid SRT blocks are skipped with a warning and processing continues for the remaining blocks.

---

### Module `frame`

#### Struct `TelemetryFrame`

Represents a single telemetry frame extracted from an SRT block.

```rust
#[derive(Debug, Clone)]
pub struct TelemetryFrame {
    pub index: u32,
    pub timestamp: Option<DateTime<Utc>>,
    pub duration_ms: u32,
    pub latitude: Option<f64>,
    pub longitude: Option<f64>,
    pub rel_alt: Option<f32>,
    pub abs_alt: Option<f32>,
    pub gimbal_yaw: Option<f32>,
    pub gimbal_pitch: Option<f32>,
    pub gimbal_roll: Option<f32>,
    pub iso: Option<u32>,
    pub shutter: Option<String>,
    pub fnum: Option<u32>,
    pub color_temp: Option<u32>,
}
```

**Fields:**

- `index` (`u32`) — SRT block sequence number (1-indexed).
- `timestamp` (`Option<DateTime<Utc>>`) — timestamp from the SRT block. `None` if parsing failed.
- `duration_ms` (`u32`) — frame duration in milliseconds (`DiffTime` field). Defaults to 33 ms if absent.
- `latitude` (`Option<f64>`) — latitude in degrees.
- `longitude` (`Option<f64>`) — longitude in degrees.
- `rel_alt` (`Option<f32>`) — relative altitude (above take-off point) in metres.
- `abs_alt` (`Option<f32>`) — absolute altitude (above sea level) in metres.
- `gimbal_yaw` (`Option<f32>`) — gimbal yaw in degrees.
- `gimbal_pitch` (`Option<f32>`) — gimbal pitch in degrees.
- `gimbal_roll` (`Option<f32>`) — gimbal roll in degrees.
- `iso` (`Option<u32>`) — camera ISO sensitivity.
- `shutter` (`Option<String>`) — shutter speed (e.g. `"1/1000"`).
- `fnum` (`Option<u32>`) — aperture value × 100 (e.g. 280 = f/2.8).
- `color_temp` (`Option<u32>`) — colour temperature in Kelvin.

#### Methods

##### `dt_seconds`

```rust
pub fn dt_seconds(&self) -> f64
```

Returns the frame duration in seconds (`duration_ms / 1000.0`). Used when accumulating trajectory time.

##### `has_gps`

```rust
pub fn has_gps(&self) -> bool
```

Returns `true` if the frame has both `latitude` and `longitude`. Used to filter frames suitable for trajectory normalisation.

### Module `parser`

#### Function `parse_file`

```rust
pub fn parse_file(path: &Path) -> Result<Vec<TelemetryFrame>, TelemetryError>
```

Reads an SRT file from disk and parses its contents.

**Parameters:**
- `path` (`&Path`) — path to the SRT file.

**Returns:** `Result<Vec<TelemetryFrame>, TelemetryError>` — vector of parsed frames or a `TelemetryError::Io` / `TelemetryError::Empty` error.

**When to use:** When the telemetry data is in a file on disk.

#### Function `parse_str`

```rust
pub fn parse_str(content: &str) -> Result<Vec<TelemetryFrame>, TelemetryError>
```

Parses SRT content provided as a string.

**Parameters:**
- `content` (`&str`) — raw SRT file content.

**Returns:** `Result<Vec<TelemetryFrame>, TelemetryError>` — vector of frames or `TelemetryError::Empty` if no block was valid.

**When to use:** When SRT content is already in memory (e.g. fetched from a network, pasted in).

**Tolerant parsing:** Invalid SRT blocks are skipped with a warning to `stderr`. An error is returned only if *no* block could be parsed.

**SRT block format:**

Each SRT block has the structure:

```
<number>
<time range>
<content: DiffTime, timestamp, key-value pairs in square brackets [ ]>
```

Key-value pairs parsed from square brackets: `iso`, `shutter`, `fnum`, `ct` (colour temperature), `latitude`, `longitude`, `rel_alt`, `abs_alt`, `gb_yaw`, `gb_pitch`, `gb_roll`. `<font>` tags are stripped automatically.

### Module `normalize`

#### Struct `TrajectoryPoint`

A single normalised trajectory point in the ENU frame.

```rust
#[derive(Debug, Clone)]
pub struct TrajectoryPoint {
    pub time: f64,
    pub position: Vector3<f64>,
    pub velocity: Option<Vector3<f64>>,
    pub frame_idx: u32,
}
```

**Fields:**
- `time` (`f64`) — time from the start of the flight in seconds (accumulated from frame `duration_ms`).
- `position` (`Vector3<f64>`) — position in the ENU (East-North-Up) frame in metres relative to the origin.
- `velocity` (`Option<Vector3<f64>>`) — velocity in m/s computed via central differences. `None` if it cannot be computed.
- `frame_idx` (`u32`) — index of the original SRT frame.

#### Struct `FlightTrajectory`

The full normalised flight trajectory.

```rust
#[derive(Debug, Clone)]
pub struct FlightTrajectory {
    pub points: Vec<TrajectoryPoint>,
    pub origin: GpsOrigin,
    pub duration_s: f64,
}
```

**Fields:**
- `points` (`Vec<TrajectoryPoint>`) — chronologically ordered trajectory points.
- `origin` (`GpsOrigin`) — GPS reference point (first frame with GPS data).
- `duration_s` (`f64`) — total trajectory duration in seconds.

**Methods:**
- `len() -> usize` — number of trajectory points.
- `is_empty() -> bool` — whether the trajectory is empty.

#### Struct `GpsOrigin`

Reference point (origin) for the GPS → ENU transform. Corresponds to the first frame with GPS data.

```rust
#[derive(Debug, Clone, Copy)]
pub struct GpsOrigin {
    pub latitude: f64,
    pub longitude: f64,
    pub altitude: f64,
}
```

**Fields:**
- `latitude` (`f64`) — latitude in degrees.
- `longitude` (`f64`) — longitude in degrees.
- `altitude` (`f64`) — relative altitude in metres.

#### Function `normalize`

```rust
pub fn normalize(frames: &[TelemetryFrame]) -> Result<FlightTrajectory, TelemetryError>
```

Converts raw telemetry frames into a normalised flight trajectory.

**Parameters:**
- `frames` (`&[TelemetryFrame]`) — parsed frames from the `parser` module.

**Returns:** `Result<FlightTrajectory, TelemetryError>` — trajectory or error.

**Behaviour:**
1. Filters frames that have GPS data (`has_gps()`) and relative altitude (`rel_alt`).
2. Determines the `GpsOrigin` reference from the first GPS frame.
3. Converts GPS coordinates of each frame to ENU using `gps_to_enu()`.
4. Computes velocity via **central differences**: for an interior point `v[i] = (pos[i+1] - pos[i-1]) / (t[i+1] - t[i-1])`; for endpoints — forward/backward difference.
5. Time is accumulated from the `duration_ms` field of successive frames.

**Errors:**
- `TelemetryError::NoGpsFrames` — no frames with GPS data.
- `TelemetryError::NotEnoughGpsFrames` — fewer than 3 GPS frames (minimum required for central-difference velocity).

#### Function `gps_to_enu`

```rust
pub fn gps_to_enu(lat: f64, lon: f64, alt: f64, origin: &GpsOrigin) -> Vector3<f64>
```

Converts GPS coordinates to a position in the local ENU (East-North-Up) frame.

**Parameters:**
- `lat` (`f64`) — latitude in degrees.
- `lon` (`f64`) — longitude in degrees.
- `alt` (`f64`) — altitude in metres.
- `origin` (`&GpsOrigin`) — reference point.

**Returns:** `Vector3<f64>` — position `(x, y, z)` in metres, where:
- `x` — eastward displacement,
- `y` — northward displacement,
- `z` — upward displacement (= altitude difference).

Flat-earth approximation with `METERS_PER_DEGREE = 111_320.0` and a cosine correction for longitude.

#### Function `enu_to_gps`

```rust
pub fn enu_to_gps(enu: &Vector3<f64>, origin: &GpsOrigin) -> (f64, f64, f64)
```

Inverse transform: ENU coordinates to GPS.

**Parameters:**
- `enu` (`&Vector3<f64>`) — position in the ENU frame in metres.
- `origin` (`&GpsOrigin`) — reference point.

**Returns:** `(f64, f64, f64)` — tuple `(latitude, longitude, altitude)` in degrees/metres.

Inverse of `gps_to_enu()`. Both functions form a bijective pair (round-trip).

### Module `error`

#### Enum `TelemetryError`

Errors generated by the telemetry parsing and normalisation pipeline.

```rust
#[derive(Debug, Error)]
pub enum TelemetryError {
    Io { path: String, source: std::io::Error },
    Empty,
    NoGpsFrames,
    NotEnoughGpsFrames { found: usize },
}
```

**Variants:**

- `Io { path: String, source: std::io::Error }` — file read error. `path` contains the file path, `source` the underlying I/O error.
- `Empty` — SRT content contained no valid telemetry blocks. The file may be empty or in an unrecognised format.
- `NoGpsFrames` — no parsed frame contains GPS data. Check whether Video Captions were enabled during the flight.
- `NotEnoughGpsFrames { found: usize }` — fewer than 3 GPS frames found (`found` holds the actual count). At least 3 frames are required for central-difference velocity computation.

## drone-analysis

### Overview

The `drone-analysis` crate validates the drone's physical model by comparing simulation results with real telemetry. The validation pipeline:

1. **Validation** (`validate`) — runs an open-loop simulation with the model's equilibrium parameters and telemetry configuration.
2. **Alignment** (`align`) — interpolates simulation results to the telemetry time points and computes errors.
3. **Report** (`report`) — aggregates error metrics and generates a human-readable report with a model quality assessment.

---

### Module `align`

#### Struct `AlignedPoint`

A single comparison point: simulation vs. telemetry at the same time instant.

```rust
#[derive(Debug, Clone)]
pub struct AlignedPoint {
    pub time: f64,
    pub sim_pos: Vector3<f64>,
    pub sim_vel: Vector3<f64>,
    pub telem_pos: Vector3<f64>,
    pub telem_vel: Vector3<f64>,
    pub pos_error: f64,
    pub vel_error: f64,
}
```

**Fields:**
- `time` (`f64`) — time instant in seconds.
- `sim_pos` (`Vector3<f64>`) — interpolated simulation position in metres.
- `sim_vel` (`Vector3<f64>`) — interpolated simulation velocity in m/s.
- `telem_pos` (`Vector3<f64>`) — telemetry position in metres.
- `telem_vel` (`Vector3<f64>`) — telemetry velocity in m/s (zero vector if unavailable).
- `pos_error` (`f64`) — Euclidean norm of position error `‖sim_pos - telem_pos‖` in metres.
- `vel_error` (`f64`) — Euclidean norm of velocity error `‖sim_vel - telem_vel‖` in m/s. 0.0 if telemetry has no velocity.

#### Struct `AlignedTrajectory`

Aligned trajectory — sequence of comparison points with aggregated metrics.

```rust
pub struct AlignedTrajectory {
    pub points: Vec<AlignedPoint>,
    pub duration_s: f64,
}
```

**Fields:**
- `points` (`Vec<AlignedPoint>`) — chronologically ordered comparison points.
- `duration_s` (`f64`) — duration of the aligned trajectory in seconds.

**Methods:**

##### `position_rms`

```rust
pub fn position_rms(&self) -> f64
```

Returns the RMS (Root Mean Square) position error in metres. Computed as `√(Σ pos_error² / n)`. Returns 0.0 for an empty trajectory.

##### `position_max`

```rust
pub fn position_max(&self) -> f64
```

Returns the maximum position error in metres across all points.

##### `velocity_rms`

```rust
pub fn velocity_rms(&self) -> f64
```

Returns the RMS velocity error in m/s. Computed analogously to `position_rms`. Returns 0.0 for an empty trajectory.

##### `to_csv`

```rust
pub fn to_csv(&self) -> String
```

Exports the aligned trajectory to CSV format. Columns: `time`, `sim_x`, `sim_y`, `sim_z`, `telem_x`, `telem_y`, `telem_z`, `pos_error`, `vel_error`.

#### Function `align`

```rust
pub fn align(sim_frames: &[SimFrame], telemetry: &FlightTrajectory) -> AlignedTrajectory
```

Aligns a simulation trajectory with a telemetry trajectory.

**Parameters:**
- `sim_frames` (`&[SimFrame]`) — simulation results (from `drone_sim::runner`).
- `telemetry` (`&FlightTrajectory`) — normalised telemetry trajectory.

**Returns:** `AlignedTrajectory` — aligned trajectory with computed errors.

**Behaviour:** For each telemetry point, linearly interpolates the simulation position and velocity to the corresponding time instant. Telemetry points outside the simulation time range use the first/last simulation frame value (constant extrapolation).

### Module `validate`

#### Struct `ValidateConfig`

Model validation configuration.

```rust
#[derive(Debug, Clone)]
pub struct ValidateConfig {
    pub dt: TimeStep,
    pub valid_position_threshold_m: f64,
}
```

**Fields:**
- `dt` (`TimeStep`) — simulation integration time step. Default: 0.02 s (50 Hz).
- `valid_position_threshold_m` (`f64`) — position error threshold in metres for computing `valid_until_s`. Default: `VALID_POSITION_THRESHOLD_M` (2.0 m).

Implements `Default` with the values above.

#### Function `validate_model`

```rust
pub fn validate_model(
    model: &dyn VehicleModel,
    telemetry: &FlightTrajectory,
    config: ValidateConfig,
    source_file: String,
) -> Result<ValidationReport, AnalysisError>
```

Runs an open-loop simulation and compares it with telemetry.

**Parameters:**
- `model` (`&dyn VehicleModel`) — drone physical model to validate.
- `telemetry` (`&FlightTrajectory`) — normalised reference trajectory.
- `config` (`ValidateConfig`) — validation configuration.
- `source_file` (`String`) — source file name (for the report).

**Returns:** `Result<ValidationReport, AnalysisError>` — validation report or `AnalysisError::EmptyTrajectory`.

**Behaviour:**
1. Sets the simulation initial state from the first telemetry point (position, velocity; attitude = identity, angular velocity = 0).
2. Runs the simulation with RK4 integration and a **constant equilibrium input** (`model.equilibrium_input()`). The simulation is intentionally open-loop — the physical model is under test, not the controller.
3. Aligns trajectories using `align()`.
4. Generates a `ValidationReport`.

### Module `report`

#### Constant `VALID_POSITION_THRESHOLD_M`

```rust
pub const VALID_POSITION_THRESHOLD_M: f64 = 2.0;
```

Default position error threshold (2.0 m) used to determine `valid_until_s`. Exposed as a public constant so `ValidateConfig` and calling code can reference it without a magic number.

#### Struct `ValidationReport`

Model validation report with aggregated metrics.

```rust
pub struct ValidationReport {
    pub source_file: String,
    pub flight_duration_s: f64,
    pub n_points: usize,
    pub position_rms_m: f64,
    pub position_max_m: f64,
    pub velocity_rms_ms: f64,
    pub valid_until_s: f64,
    pub trajectory: AlignedTrajectory,
}
```

**Fields:**
- `source_file` (`String`) — telemetry source file name.
- `flight_duration_s` (`f64`) — flight duration in seconds.
- `n_points` (`usize`) — number of comparison points.
- `position_rms_m` (`f64`) — RMS position error in metres.
- `position_max_m` (`f64`) — maximum position error in metres.
- `velocity_rms_ms` (`f64`) — RMS velocity error in m/s.
- `valid_until_s` (`f64`) — time (in seconds from start) up to which the position error does not exceed the threshold. Defined as the time of the last consecutive point with `pos_error < valid_threshold_m` (counting from the start).
- `trajectory` (`AlignedTrajectory`) — full aligned trajectory for further analysis or export.

**Methods:**

##### `from_aligned`

```rust
pub fn from_aligned(
    aligned: AlignedTrajectory,
    source_file: String,
    valid_threshold_m: f64,
) -> Self
```

Constructor that builds a report from an aligned trajectory.

**Parameters:**
- `aligned` (`AlignedTrajectory`) — aligned trajectory.
- `source_file` (`String`) — source file name.
- `valid_threshold_m` (`f64`) — position error threshold for computing `valid_until_s`.

##### `print`

```rust
pub fn print(&self)
```

Prints a formatted report to `stdout` with an ASCII border. Includes a model quality assessment:
- **Excellent** — RMS < 0.5 m
- **Good** — RMS < 2.0 m
- **Approximate** — RMS < 5.0 m
- **Poor** — RMS ≥ 5.0 m (model parameter verification recommended)

##### `to_csv`

```rust
pub fn to_csv(&self) -> String
```

Delegates to `AlignedTrajectory::to_csv()`. Returns trajectory data in CSV format.
